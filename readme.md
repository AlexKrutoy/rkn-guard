## Установка

Для установки нужны Linux с systemd, `curl` и права root или `sudo`. Установщик скачает готовый бинарник и поставит зависимости.

```bash
curl -fsSL https://raw.githubusercontent.com/AlexKrutoy/rkn-guard/master/install.sh | sudo bash -s -- install
```

Автоматический режим определяет текущий межсетевой экран и выбирает nftables на чистом сервере. Вручную можно выбрать nftables, iptables + ipset (в том числе с UFW) или активный firewalld с бэкендом nftables.

## Переход между dev и master на установленном сервере

В форке сейчас есть только ветка `master`, поэтому переход на `dev` сработает лишь после того, как вы создадите эту ветку в своём репозитории. Механизм обновления из стабильного релиза работает как в оригинале.

Команды выполняются на Linux-сервере с установленным rkn-guard и systemd. Для сборки нужны Git и Go версии из go.mod (сейчас 1.25.3) или Go 1.21+ с доступной автоматической загрузкой toolchain. Нужен доступ к GitHub и зависимостям Go. На Debian/Ubuntu установите инструменты через apt, на Fedora/RHEL-подобных системах — через dnf.

| ОС | Подготовка |
| --- | --- |
| Debian / Ubuntu | `sudo apt-get update && sudo apt-get install -y git golang-go curl openssh-server sudo` |
| Fedora / Rocky / AlmaLinux | `sudo dnf install -y git golang curl openssh-server sudo` |

Проверьте `go version`. Если дистрибутив поставляет более старую версию, установите актуальный Go с https://go.dev/doc/install в /usr/local/go. Для переключения скачайте скрипт и запустите его с именем ветки. Он собирает бинарник и ставит меню из одного коммита, сохраняя действующие правила и счётчики.

**Перейти на dev**

```bash
switcher=$(mktemp) && curl -fsSLo "$switcher" https://raw.githubusercontent.com/AlexKrutoy/rkn-guard/master/switch-branch.sh &&
sudo bash "$switcher" dev && rm -f "$switcher"
rkn-guard build-info
sudo rkn
```

**Вернуться на master**

```bash
switcher=$(mktemp) && curl -fsSLo "$switcher" https://raw.githubusercontent.com/AlexKrutoy/rkn-guard/master/switch-branch.sh &&
sudo bash "$switcher" master && rm -f "$switcher"
rkn-guard build-info
```

Для перехода на master с сохранением привязки скачивайте switch-branch.sh из master. Вторая строка build-info показывает установленную ветку. Меню master обновляет программу из стабильного релиза.

### Подключение к панели

Скачайте [rkn-guard-panel для Windows](https://github.com/Flecksis/rkn-guard-panel/releases/latest). Панель показывает нагрузку, отброшенные пакеты и историю по серверам. В ней можно менять ручные баны, исключения, источники и расписание, обновлять и переустанавливать rkn-guard на нескольких узлах.

Откройте `sudo rkn` → **9. Подключить к панели rkn-guard-panel**, прочитайте условия и разрешите привязку. Меню берёт адрес и порт сервера из SSH-сеанса. Без данных сеанса оно использует исходящий адрес сервера и порт sshd. Если у сервера NAT с пробросом портов, выдайте код с внешним адресом и портом командой `sudo rkn-guard panel issue ВНЕШНИЙ_АДРЕС ВНЕШНИЙ_ПОРТ`. Требуются Python 3.8+, sudo, стандартный файл .ssh/authorized_keys, публичная аутентификация, разрешённый вход rkn-guard-user и ключ хоста Ed25519. Новый порт открывать не требуется.

В приложении нажмите **Добавить по коду**, вставьте строку RKN1 и задайте имя сервера. Код содержит временный приватный ключ, действует пять минут и погашается при первом обмене. Постоянный приватный ключ создаёт приложение. Панель проверяет ключ хоста и выполняет мониторинг, обновление и удаление через SSH. При смене IP обновите адрес в профиле или используйте стабильное DNS-имя.

Для отзыва выберите **Удалить привязку к панели rkn-guard-panel** или выполните `sudo rkn-guard panel revoke`. Это также позволяет заменить истёкший код. Удаление rkn-guard удаляет серверные файлы привязки, правило sudo и служебного пользователя. Профиль и история в приложении остаются на вашем компьютере.

## Управление

Откройте меню после установки.

```bash
rkn
```

| Раздел меню | Что можно сделать |
| --- | --- |
| Статистика и журналы | Найти самые частые IP источников или посмотреть новые события отдельно для IPv4 и IPv6 |
| Управление IP | Заблокировать адрес вручную или добавить исключение для нужного порта |
| Обновление списков и расписание | Применить свежие подсети сразу или настроить таймер |
| Доп списки подсетей | Подключить собственный источник и управлять им отдельно |
| Адаптивный щит | Включить автобан сканеров по числу соединений, посмотреть и снять баны |
| Обновить rkn-guard и меню | Загрузить новую версию программы и меню |
| Переустановить / Удалить | Повторить установку или снять правила и удалить меню |

## Адаптивный щит

Списки подсетей закрывают известных сканеров, но не того, кто пришёл с чистого адреса и начал долбиться в 443 сотнями соединений в секунду. Для этого в `rkn-guard` есть второй контур — адаптивный щит на `nftables`. Он считает новые соединения средствами ядра и банит источник на время. Логи не парсятся: у Xray, sing-box и 3x-ui форматы разные, а счётчики conntrack одинаковые, поэтому щит работает с любым VPN-ядром и не ломается при его обновлении.

Логика правил в отдельной таблице `inet rkn_guard_dynamic`:

```
новое соединение на 443
        │
        ├─ established/related ────────────────► пропустить
        ├─ адрес в белом списке ───────────────► пропустить
        ├─ адрес в бане ───────────────────────► drop
        └─ больше 300 новых за минуту ──────────► в бан на час, drop
```

Что здесь важнее всего:

* **Белый список проверяется первым правилом.** В нём loopback, приватные сети и CGNAT `100.64.0.0/10` — за ним сидят мобильные операторы, и одна ошибка там отрезала бы разом много клиентов. Свои записи добавляются флагом `--allow` или командой `guard allow add`.
* **Автобан кладёт только одиночный адрес.** Подсеть автобаном не блокируется никогда, это проверяется тестом, а не обещанием в README.
* **У бана всегда есть срок.** По умолчанию час. Ошиблись — рассосётся само.
* **Отказ вместо самострела.** Если правила отрежут текущую SSH-сессию, щит не применяет ничего и говорит почему. Адрес сессии попадает в белый список до применения правил, а не после.
* **Своя таблица.** Чужие правила `iptables`, `nftables` и `ufw` не трогаются, откат — удаление одной таблицы без побочных эффектов.

```bash
sudo rkn-guard guard                 # состояние щита
sudo rkn-guard guard plan            # правила, которые будут применены
sudo rkn-guard guard apply           # включить
sudo rkn-guard guard top             # кто сейчас в бане
sudo rkn-guard guard rollback        # снять всё одной командой
```

Порог, срок бана и порты задаются профилем или флагами.

| Профиль | Новых соединений в минуту | Срок бана |
| --- | --- | --- |
| `relaxed` | 900 | 10m |
| `basic` | 600 | 15m |
| `enhanced` | 300 | 1h |
| `strict` | 100 | 6h |
| `custom` | `--rate` | `--ban-time` |

```bash
sudo rkn-guard guard apply --level strict --ports 443,8443
sudo rkn-guard guard apply --level custom --rate 40 --ban-time 2h
sudo rkn-guard guard ban 198.51.100.7 --for 30m
sudo rkn-guard guard unban 198.51.100.7
sudo rkn-guard guard allow add 203.0.113.0/24
```

Щит поднимается при загрузке службой `rkn-guard-guard.service`, баны переживают перезагрузку и восстанавливаются со своим остатком срока. Внешние списки адресов подключаются командой `guard feed add URL`: из них берутся только одиночные адреса и узкие подсети, а всё, что пересекается с белым списком, вырезается до применения.

Идея второго контура и правила «белый список первым, бан только по адресу и только со сроком» взяты из проекта [HUBGuard](https://github.com/qwe8nxtroud/HUBGuard). Здесь они переписаны на Go и встроены в общий CLI и установщик `rkn-guard`.

<summary>Команда rkn, версия и справка CLI</summary>

| Команда | Назначение |
| --- | --- |
| `sudo rkn` или `sudo rkn monitor` | Открыть интерактивное меню |
| `sudo rkn install` | Запустить установку с выбором firewall |
| `sudo rkn update` | Обновить списки с теми же источниками, что у меню и таймера |
| `sudo rkn uninstall` | Запустить удаление с подтверждением |
| `rkn-guard --version` | Показать версию бинарника |
| `rkn-guard build-info` | Вывести версию и ветку сборки отдельными строками |
| `sudo rkn-guard panel issue АДРЕС ПОРТ` | Выдать одноразовый код на пять минут для указанного адреса и порта SSH |
| `sudo rkn-guard panel revoke` | Отозвать код и постоянный ключ, удалить служебного пользователя панели |
| `rkn-guard panel --help` | Показать команды привязки |
| `rkn-guard --help` | Показать доступные команды |
| `rkn-guard help full` или `rkn-guard full --help` | Посмотреть синтаксис и параметры конкретной команды |
| `rkn-guard completion bash` | Вывести скрипт автодополнения. Также доступны `zsh`, `fish` и `powershell` |

Общие параметры CLI: `--log-level` задаёт подробность сообщений (`debug`, `info`, `warn`, `error`), а `--sources-file` указывает файл настроек и кэша источников. По умолчанию это `/var/lib/rkn-guard/sources.json`.

<details>
<summary>Настройка firewall и обновление по URL</summary>

| Команда | Что делает |
| --- | --- |
| `sudo rkn-guard firewall-select auto` | Проверяет совместимость и выводит выбранный бэкенд. Можно указать конкретный режим: `iptables`, `nftables` или `firewalld` |
| `sudo rkn-guard firewall-status` | Показывает сохранённый режим. Для nftables и firewalld также выводит число подсетей |
| `sudo rkn-guard firewall-restore` | Служебная команда systemd для восстановления сохранённых правил nftables и firewalld после загрузки |

Для обычной установки используйте скрипт из начала README. Если вы задаёте источники самостоятельно, команда `full` применяет правила и настраивает их восстановление. В этом примере используется один основной список.

```bash
LIST_URL=https://raw.githubusercontent.com/shadow-netlab/traffic-guard-lists/refs/heads/main/public/government_networks.list
sudo rkn-guard full --firewall auto --urls "$LIST_URL" --enable-logging
```

Чтобы обновить наборы с тем же URL и сохранить счётчики, выполните в той же оболочке:

```bash
sudo rkn-guard update -u "$LIST_URL"
```

`-u` — короткая форма `--urls`, а `-l` — короткая форма `--enable-logging` для `full`. Флаг `--managed-lists` у команд `full` и `update` подключает настройки источников и проверенные копии списков. При частичном обновлении `update` возвращает код 2. Для применения всех списков из конфигурации меню используйте `sudo rkn update`.

</details>

<details>
<summary>Списки и расписание</summary>

В разделе «Доп списки подсетей» добавьте HTTP(S)-ссылку на текстовый файл с IPv4/IPv6-подсетями в формате CIDR. После проверки источник появится выключенным. Включите его в меню, чтобы применить список.

В CLI действия с источниками сохраняют настройки. Примените их командой `sudo rkn update`. В примерах замените URL на адрес своего списка, а `1` — на номер из соответствующего списка.

| Дополнительные источники | Действие |
| --- | --- |
| `sudo rkn-guard sources add https://example.org/networks.txt` | Проверить файл и добавить источник |
| `sudo rkn-guard sources list` | Посмотреть номера, состояние и сведения о последних загрузках |
| `sudo rkn-guard sources enable 1` | Включить источник |
| `sudo rkn-guard sources enable URL` | Выбрать источник по адресу вместо локального номера. Адрес также принимают `disable`, `remove`, `base-enable` и `base-disable` |
| `sudo rkn-guard sources disable 1` | Временно отключить источник |
| `sudo rkn-guard sources remove 1` | Удалить источник из конфигурации |

**Основные источники.** Меню передаёт их адреса автоматически. При прямом вызове передайте по одному `--base-url` на каждый основной URL в том же порядке. Ниже пример для конфигурации с одним основным списком. Каждая строка иллюстрирует отдельное действие.

```bash
BASE=https://raw.githubusercontent.com/shadow-netlab/traffic-guard-lists/refs/heads/main/public/government_networks.list
sudo rkn-guard sources base-list --base-url "$BASE"
sudo rkn-guard sources base-disable 1 --base-url "$BASE"
sudo rkn-guard sources base-enable 1 --base-url "$BASE"
```

Параметр `--base-url` также позволяет `sources add` проверить, что новый URL ещё не входит в основные источники.

При установке ответ `y` включает ежедневное обновление в 06:00 по местному времени сервера. В меню можно задать интервал от 1 до 168 часов или конкретное время по Москве, например `06:00,18:30`.

Проверить таймер и результат последнего обновления можно через systemd.

```bash
systemctl list-timers --all rkn-guard-update.timer
journalctl -u rkn-guard-update.service -n 50 --no-pager
```

</details>

<details>
<summary>Ручная блокировка и исключения</summary>

Пример ручного бана, просмотра и удаления записи.

```bash
sudo rkn-guard manual-ips add 192.0.2.10
sudo rkn-guard manual-ips list
sudo rkn-guard manual-ips delete 192.0.2.10
```

Исключение действует для одного IP источника, протокола и порта назначения. Остальные правила межсетевого экрана продолжают действовать. Удаление ручного бана снимает отдельную запись. Адрес внутри заблокированной подсети по-прежнему попадает под её правило.

```bash
sudo rkn-guard exceptions add 192.0.2.10 tcp 443
sudo rkn-guard exceptions list
sudo rkn-guard exceptions delete 192.0.2.10 tcp 443
```

</details>

<details>
<summary>Журналы и статистика</summary>

```bash
sudo rkn-guard stats
sudo rkn-guard logs v4
sudo rkn-guard logs v6
```

Статистика группирует записанные события по IP источника. Ограничение частоты записи в журнал влияет на итоговые числа. Просмотр журнала завершается по Ctrl+C. Для восстановления сбора событий выполните `sudo rkn-guard setup-logging`.

</details>

<details>
<summary>Удаление</summary>

**Чтобы снять защиту и удалить меню**, выберите **9 → Удалить** или выполните `sudo rkn uninstall` и подтвердите действие буквой `y`. Менеджер отключает расписание, вызывает деинсталлятор и удаляет команду `rkn` и скрипт меню.

**Чтобы удалить правила вместе с журналами и статистикой**, используйте CLI:

```bash
sudo rkn-guard uninstall --remove-logs
```

Деинсталлятор очищает правила и наборы проекта, ручные баны и исключения, службы и таймеры systemd, конфигурацию rsyslog и logrotate. Флаг `--remove-logs` дополнительно удаляет файлы `/var/log/iptables-scanners-*`, включая CSV и ротированные журналы, а также сохранённые счётчики. По умолчанию история сохраняется. Для запуска из сценария флаг `--yes` пропускает запрос подтверждения.

Сам бинарник `rkn-guard`, файл источников с кэшем и установленные системные пакеты могут остаться на сервере. При прямом вызове CLI также остаётся меню.

</details>

Используйте rkn-guard для фильтрации входящих подключений на своих серверах или там, где владелец поручил вам управлять сетевым доступом.
